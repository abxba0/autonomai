## Legal Framework

### Applicable Legislation

1. **UK GDPR** - General Data Protection Regulation (UK version)
2. **Data Protection Act 2018** - UK implementation and supplementary provisions
3. **Privacy and Electronic Communications Regulations (PECR)**

### Legal Basis for Processing

Our primary lawful bases for processing personal data are:

- **Consent** (Article 6(1)(a)): For optional features and marketing
- **Contract** (Article 6(1)(b)): For service provision to users
- **Legitimate Interests** (Article 6(1)(f)): For system security and fraud prevention
- **Legal Obligation** (Article 6(1)(c)): For compliance with legal requirements

## Data Collection & Processing

### Types of Personal Data Collected

#### 1. User Account Data
- **Username**: Unique identifier for user accounts
- **Email Address**: For account verification and communications
- **Password Hash**: Securely hashed using industry-standard algorithms (bcrypt/argon2)

- **Last Login**: Last successful login timestamp

#### 2. Authentication Data
- **API Keys**: Hashed API keys for programmatic access
- **JWT Tokens**: Short-lived access tokens and refresh tokens
- **Session Data**: Redis-based session management (if enabled)

#### 3. Audit & Security Data
- **IP Addresses**: For security monitoring and fraud prevention
- **User Agent Strings**: Browser/client identification for security
- **Request Timestamps**: For rate limiting and security analysis
- **Security Events**: Failed login attempts, permission denials, suspicious activities
- **Audit Logs**: Comprehensive logs of all data access and modifications

#### 4. System Usage Data
- **Query History**: User queries submitted to the system
- **Model Outputs**: Responses generated by AI models
- **Feedback**: User-provided corrections and feedback
- **Failure Logs**: System failures and optimization attempts
- **Conversation Context**: Historical conversation data for context

#### 5. Tenant-Specific Data (Multi-tenant Mode)
- **Tenant ID**: Unique identifier for organizational tenants
- **Tenant Name**: Organization name
- **Configuration Settings**: Tenant-specific system settings
- **Resource Usage Metrics**: Usage statistics and quotas

### Data Processing Activities

#### Purpose of Processing
1. **Service Delivery**: Providing self-optimizing AI instruction services
2. **System Optimization**: Learning from failures to improve instruction quality
3. **Security & Fraud Prevention**: Protecting user accounts and system integrity
4. **Compliance**: Meeting legal and regulatory obligations
5. **Customer Support**: Responding to user inquiries and issues

#### Data Storage Locations
- **Primary Storage**: SQLite database (development) / PostgreSQL (production)
- **File Storage**: Local filesystem for instruction versions and markdown files
- **Cache Storage**: Redis (optional, for session management and rate limiting)
- **Audit Logs**: Separate audit database and log files
- **Backup Storage**: Encrypted backups with retention policy

#### Data Retention Periods
- **Active User Accounts**: Retained while account is active
- **Inactive Accounts**: Deleted after 24 months of inactivity (configurable)
- **Audit Logs**: Retained for 7 years (UK legal requirement)
- **Session Data**: Expired after 30 days of inactivity
- **Failure Logs**: Retained for 90 days, then archived/anonymized
- **Backup Data**: Retained for 30 days

## User Rights Implementation

The system implements all UK GDPR user rights through dedicated API endpoints:

### Right to Access (Article 15)

**Implementation**: `/gdpr/access` endpoint

Users can request all personal data held about them, including:
- User account information
- Authentication records (excluding sensitive hashes)
- Audit logs related to the user
- Query history and feedback
- System configuration specific to the user

**Response Format**: JSON or CSV export
**Response Time**: Within 30 days (as required by UK GDPR)

### Right to Rectification (Article 16)

**Implementation**: `/gdpr/rectify` endpoint

Users can update incorrect or incomplete personal data:
- Email address updates
- Username changes (with appropriate verification)
- Profile information corrections

**Process**: Automated with audit trail of all changes

### Right to Erasure (Article 17)

**Implementation**: `/gdpr/delete` endpoint

Users can request deletion of their personal data when:
- Data is no longer necessary for original purpose
- Consent is withdrawn
- Data is unlawfully processed
- Legal obligation requires deletion

**Process**:
1. Soft delete: Account marked as deleted, data anonymized
2. Hard delete: Complete removal from all systems (after retention period)
3. Audit logs: Retained for legal compliance (anonymized user reference)
4. Backups: Data removed from future backups, existing backups expire

**Exceptions**: Data retained where legally required (e.g., audit logs for 7 years)

### Right to Data Portability (Article 20)

**Implementation**: `/gdpr/export` endpoint

Users can export their data in a machine-readable format:
- **Format**: JSON (primary), CSV (alternative)
- **Includes**: All personal data provided by or generated for the user
- **Excludes**: System-internal data not relevant to the user

### Right to Restrict Processing (Article 18)

**Implementation**: Account suspension feature

Users can restrict processing of their data while disputes are resolved:
- Account marked as "restricted"
- No processing except storage
- User notified before restrictions lifted

### Right to Object (Article 21)

**Implementation**: Opt-out mechanisms

Users can object to processing based on legitimate interests:
- Security monitoring (with limitations for fraud prevention)
- Analytics and system optimization
- Marketing communications

## Data Security Measures

### Encryption

1. **In Transit**
   - TLS 1.3 for all API communications
   - HTTPS enforced for web interface
   - Certificate-based authentication for inter-service communication

2. **At Rest**
   - Password hashing using bcrypt/argon2 (configurable)
   - API key hashing using SHA-256 with salt
   - Database encryption (optional, recommended for production)
   - Encrypted backups using AES-256

### Access Controls

1. **Authentication**
   - Multi-factor authentication support (optional)
   - Password complexity requirements
   - Account lockout after failed attempts
   - Session timeout (30 minutes default)

2. **Authorization**
   - Role-Based Access Control (RBAC)
   - Granular permission system
   - Least privilege principle
   - Regular access reviews

### Monitoring & Detection

1. **Security Monitoring**
   - Real-time security event detection
   - Anomaly detection for suspicious activity
   - Failed authentication tracking
   - Rate limiting to prevent abuse

2. **Audit Logging**
   - Comprehensive audit trail (20+ event types)
   - Tamper-evident logs
   - Regular log review
   - Automated alerting for security events

### Data Minimization

- Only collect data necessary for service provision
- Automatic deletion of unnecessary data
- Anonymization where possible
- Pseudonymization for analytics

## Data Retention & Deletion

### Retention Policy

| Data Type | Retention Period | Justification |
|-----------|-----------------|---------------|
| Active User Accounts | While active | Service provision |
| Inactive User Accounts | 24 months | Re-engagement opportunity |
| Audit Logs | 7 years | Legal requirement (UK) |
| Query History | 90 days | System optimization |
| Failure Logs | 90 days (then anonymized) | System improvement |
| Session Data | 30 days | Security |
| Backup Data | 30 days | Disaster recovery |
| Security Events | 12 months | Security analysis |
| Financial Records | 7 years | Legal requirement |

### Automated Deletion

Implemented automated processes for:
- Expired session cleanup (daily)
- Inactive account deletion (monthly check)
- Log rotation and archival (weekly)
- Backup expiration (daily)
- Anonymization of old data (weekly)

### Deletion Procedures

1. **User-Requested Deletion** (Right to Erasure)
   - Immediate soft delete (account deactivated)
   - 30-day grace period (for accidental deletion)
   - Hard delete after grace period
   - Audit trail maintained (anonymized)

2. **Automatic Deletion**
   - Scheduled tasks for data cleanup
   - Compliance with retention policy
   - Audit trail of deletions
   - Verification and reporting

## Consent Management

### Consent Requirements

1. **Freely Given**: Users must have genuine choice
2. **Specific**: Separate consent for different purposes
3. **Informed**: Clear explanation of data use
4. **Unambiguous**: Clear affirmative action required

### Consent Tracking

The system tracks:
- **Consent Given**: Timestamp and method
- **Consent Purpose**: What data processing was consented to
- **Consent Version**: Version of privacy policy accepted
- **Consent Withdrawal**: When and how consent was withdrawn

### Consent Management API

Endpoints:
- `POST /consent/grant`: Record user consent
- `GET /consent/status`: Check current consent status
- `POST /consent/withdraw`: Withdraw specific consent
- `GET /consent/history`: View consent history

## Breach Notification

### Detection

- Automated security monitoring
- Anomaly detection
- Regular security assessments
- Vulnerability scanning

### Notification Timeline

**UK GDPR Requirements**:
- **ICO Notification**: Within 72 hours of breach discovery
- **User Notification**: Without undue delay (if high risk to users)

### Notification Process

1. **Discovery**: Breach detected by monitoring systems
2. **Assessment**: Determine scope and impact
3. **Containment**: Immediate measures to limit breach
4. **Documentation**: Record all details for ICO
5. **Notification**: Notify ICO and affected users
6. **Remediation**: Implement fixes and improvements
7. **Review**: Post-incident analysis

### Breach Response Team

- **Data Protection Officer**: Lead coordinator
- **Security Team**: Technical investigation
- **Legal Team**: Regulatory compliance
- **Communications**: User notification
